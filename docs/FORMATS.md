# File formats

QuillPress recognizes files by their **content, not their extension** (`sniffFormat` in `src/io/index.ts`): a misnamed file opens with the right reader. Damaged files go through the recovery pipeline automatically ([RECOVERY.md](RECOVERY.md)).

This file describes what is implemented now. The longer list of page layout formats QuillPress intends to read is in [FORMATS-PLAN.md](FORMATS-PLAN.md).

## QuillPress publication (.qpp)

A ZIP package, in the OpenDocument tradition:

- `mimetype`, stored first and uncompressed, containing `application/x-quillpress`, so file identifiers and the recovery engine recognize the type from the first bytes;
- `publication.json`: `{ format: "quillpress", version, data, media }`, where `data` is the `Publication` of `src/model/types.ts` (pages, masters, stories, styles, swatches, layers, sections, variables, baseline grid, properties) and `media` lists every picture by id;
- `media/<id>.<ext>`: the pictures themselves (PNG, JPEG, GIF, WebP, BMP, TIFF, SVG), referenced from `media` so the JSON stays small.

`.json` is the same `publication.json` with the pictures embedded as base64, for scripts and bug reports. `.qppe` is the `.qpp` bytes encrypted with AES-256-GCM (PBKDF2 key derivation, magic `QFDE1`); the password is never stored.

Units are points (1/72 in) throughout; the `unit` field only sets what rulers and dialogs show.

## Scribus (.sla)

Scribus 1.4 and 1.5 documents (the open `SCRIBUSUTF8NEW` XML) open and save.

**Imported:** page size, orientation, facing pages (`BOOK`), bleed, margins and columns of the document and of each `MASTERPAGE`; pages with their master; `PAGEOBJECT` and `MASTEROBJECT` frames of type text (4, and 8 text on path, as a text frame), picture (2), shape (6 as a preset or custom path; 7 polyline), line (5), table (16, grid only) and group (12, with the members Scribus 1.5 nests inside the group element; groups whose members cannot be read are dropped); position, size, rotation, fill and line colors with line width, lock, name and text wrap mode; text frames' columns, gap, insets, vertical alignment and **chains** (`NEXTITEM`/`BACKITEM` by `ItemID`, `NUMPO` or document order); the story text with paragraph styles (`STYLE`, `PARENT`), local alignment, fonts (`Family Bold Italic` names map to bold/italic), sizes and colors; `COLOR` swatches given as RGB or CMYK; embedded pictures (`ImageData`); referenced pictures are recorded by file name as empty frames with a warning (use Tools ▸ Relink Picture).

**Exported:** the same set in reverse (groups are written as their members, ungrouped). Paragraph styles become `STYLE` elements; swatches become `COLOR`; pictures are embedded as `ImageData`; frames of a story carry `NEXTITEM`/`BACKITEM`; objects on masters are `MASTEROBJECT`. Effects, baseline grid, comments and variables have no Scribus equivalent and are dropped (Save warns and offers .qpp).

The round trip is tested in `tests/unit/io.test.ts`. The reader is tolerant: unknown elements are ignored, and a truncated file is healed by the recovery engine.

## InDesign (.idml, .indd)

**IDML** is Adobe's documented interchange package: a ZIP of XML files. `src/io/idml.ts` reads the package and `src/io/idmlText.ts` its resources and stories.

**Imported:** page size, facing pages, bleed and the display unit (`Resources/Preferences.xml`); layers; master spreads (one QuillPress master per master-spread page, named *A-Master (Left)* / *(Right)* for facing pages) with their margins, columns and items; spreads with pages, each page's margins and columns, and the master applied by side; sections (page numbering) and custom text variables; `Resources/Graphic.xml` colors (CMYK, RGB and Lab), tints and gradients as swatches and fills; `Resources/Styles.xml` paragraph styles (size, font, bold/italic, alignment, indents, spacing, leading, hyphenation, drop caps, keep options, bullets and numbering, tabs, rules, based-on and next style), character styles and object styles; text frames with columns, gutter, insets, vertical alignment, auto-size, ignore-wrap and their story **chains** (`PreviousTextFrame`/`NextTextFrame`); rectangles, ovals, polygons (as custom paths), lines and groups with fills, strokes, dashes, opacity, rotation (from `ItemTransform`), lock, visibility, names and text wrap; picture frames with the picture when it is embedded in the package, otherwise the linked file's name (IDML does not carry linked pictures: the frame is kept and the warning lists the names for Tools ▸ Relink Picture); stories with paragraph and character style ranges and local overrides, forced line breaks, tabs, text variables, hyperlinks' text, tables (as tab-separated rows) and footnotes (into the publication's footnotes when the model has them, otherwise as a *Notes* list at the end of the story). Objects anchored in text are placed as free objects near the story's first frame.

**Not imported:** buttons, forms, sounds and movies (counted in the warning), XML structure, conditional text, object effects beyond opacity, and InDesign's own typesetting (optical kerning, justification settings), so lines break where QuillPress breaks them.

**Exported (File ▸ Save As / Export ▸ InDesign Markup):** `src/io/idmlExport.ts` and `src/io/idmlExportText.ts` write a package laid out as the IDML specification requires: `mimetype` first and stored, `designmap.xml` (with `idPkg:` references to every part, layers, sections, text variables and hyperlinks), `META-INF/container.xml` and `metadata.xml` (XMP title, author, description, keywords), `Resources/Fonts.xml`, `Graphic.xml`, `Preferences.xml`, `Styles.xml`, one `MasterSpreads/MasterSpread_*.xml` per master (a facing pair *X (Left)* / *X (Right)* becomes one two-page master spread), one `Spreads/Spread_*.xml` per page or facing pair, `Stories/Story_*.xml`, `XML/BackingStory.xml` and `XML/Tags.xml`. Every element carries a `Self` id.

What is written:

- Page size, facing pages, bleed, the display unit, the baseline grid and the footnote options (`Preferences.xml`); pages with their margins and columns (`MarginPreference`), the master applied to each page, page labels, sections with their numbering style, start and prefix, and custom text variables.
- Swatches as `Color` elements: CMYK when the swatch's CMYK values reproduce its screen color, RGB otherwise (so the color the publication shows survives a round trip); `Black` and `Paper` are the built-in colors, `None` is `Swatch/None`; hex colors used directly on objects or text become `R=… G=… B=…` colors; gradient fills become `Gradient` swatches; a dash-dot stroke adds a `DashedStrokeStyle`, the other dashes use InDesign's built-in styles.
- Paragraph styles (font, size, bold/italic, color, alignment, indents, space before and after, leading in points — percent leading is converted with the style's size and kept as `AutoLeading` —, hyphenation, drop caps, keep options, baseline alignment, bullets and numbering, tab stops, rules, based-on and next style), character styles and object styles (fill, stroke, insets, columns). `Body` is also written as InDesign's `NormalParagraphStyle`.
- Text frames with their story, chain (`PreviousTextFrame`/`NextTextFrame`), columns, gutter, insets, vertical alignment, auto-size, ignore-wrap and first-baseline option; rectangles, ovals and polygons (preset and custom shapes as Bézier `PathGeometry`), lines with arrowheads, groups; pictures as a frame holding an `Image` whose bytes are embedded in `Contents` (base64) with a `Link` naming the file, so the package needs no external files; rotation and flips through `ItemTransform`; opacity (`BlendingSetting`), text wrap (`TextWrapPreference`), layers (`ItemLayer`), lock, visibility, names and alternative text.
- Stories as `ParagraphStyleRange` / `CharacterStyleRange` with local overrides, forced line breaks (`&#x2028;`), tabs, hyperlinks (`HyperlinkTextSource` plus `Hyperlink` destinations in the design map), footnotes as `Footnote` elements, objects anchored in text nested in their character range with an `AnchoredObjectSetting`, fields as their last displayed text, and tables as InDesign tables (`Table`/`Row`/`Column`/`Cell`) in a story shown by a text frame at the table's position. Text on a path is written as the path with a `TextPath` child and its own story.

Known losses (what InDesign will not see, or what a round trip through QuillPress changes):

- Picture crop, fit and position inside the frame become a fitting option only; picture adjustments (brightness, contrast, saturation, grayscale), image fills and pattern fills, effects (shadow, glow, soft edge), the `behind` wrap mode, guides, page notes, comments and the document's Quick Access Bar are not written.
- Fields (page numbers, dates, variables) are written as their last displayed text, not as live InDesign markers.
- Re-importing a package QuillPress wrote: tables come back as tab-separated rows in a text frame (the importer flattens tables); text on a path comes back as its path only (the importer does not read `TextPath`); anchored objects come back as free objects near their story's first frame; a flipped object comes back rotated rather than flipped, and a shape made from a preset comes back as a custom path with the path's own bounds as its box (a preset whose drawing does not fill its box, such as a star, shrinks to the drawing).

**.indd** (the binary document) has no public specification. QuillPress identifies it by its header and recovers its text (UTF-16 runs) and embedded pictures into frames you can lay out again. Ask InDesign for an IDML export for the real layout.

## Microsoft Publisher (.pub)

A Publisher file is an OLE2 compound file ([MS-CFB], read by `src/io/cfb.ts`) with a `Contents` stream (the document, pages, shapes, tables, palette and fonts as typed chunks), a `Quill` stream (the text as UTF-16 with character and paragraph formatting runs, style sheets, fonts and colors) and `Escher` streams (the shapes' geometry and the pictures as Office Art records, [MS-ODRAW]). Publisher's own structures are not published by Microsoft; `src/io/mspub/` reads them from the public description embodied in the Document Liberation Project's reader (see docs/LEGAL.md, *Format references*) and is original code. What is read:

- **Publisher 2002–2016:** page size; every page in document order; master pages as masters with their items and the master applied to each page; the page background; shapes with position, size, rotation, flips, z-order and groups (child positions scaled to the group box); text boxes as text frames with insets, columns, gutter and vertical alignment, boxes that show the same text chained in placement order; text with font names, sizes, bold, italic, underline (single, double, wavy), color (palette entries become "Scheme Color n" swatches; direct RGB becomes hex), superscript and subscript, small and all caps, language; paragraph alignment, indents, space before and after, line spacing (points or percent), tabs, bullets and numbering, drop caps; tables as table items (column widths, row heights, spans, cell text); pictures (PNG, JPEG, TIFF and DIB) placed in their frames with brightness and contrast; solid fills with opacity, gradients, picture and pattern fills; outlines with width, dash, arrowheads and caps; shadows; text wrap as square wrap.
- **Publisher 2000:** page size, pages, the one master applied to every page, text boxes with their Quill text and formatting, rectangles, ellipses, lines and the autoshape table, solid fills, outlines, rotation and flips, the palette.
- **Publisher 97/98:** the same shapes with that version's record layout; text from the `Contents` stream (8-bit, paragraphs at line ends) with bold, italic, underline, size and color spans; no fonts or paragraph formatting.
- **Not read** (each counted in a warning): Border Art, embedded fonts (names kept), field codes, preset adjust values, computed vertices of custom shapes, per-side outline differences, crop types, Macintosh PICT pictures and metafiles that draw nothing (left as empty frames naming the picture). WMF and EMF pictures are converted to vector drawings by `src/io/metafile/` (47 of the 49 in the seed corpus; the other two hold only a header); text inside them uses the fonts installed on the device, since an SVG picture cannot use the app's web fonts.

When the version is unknown or parsing fails, the reader falls back to the earlier method: the text of the `Quill` stream and every picture found by signature, placed in flowing frames, with a warning. The reader was written from the format description and verified on files built in code, on three files saved by Publisher 2007-era builds (a restaurant menu and two weekly schedules with tables, groups and placed JPEGs) and on the 31-file Publisher seed corpus of the Document Liberation Project (Publisher 97, 2000, 2002–2010 files exercising tables, merged cells, text and paragraph formatting, fonts, languages, borders, WordArt and multi-page brochures and newsletters): 30 read with their layout and one, which is not a compound file at all, takes the byte-level fallback. The unit tests run against those files when they are present under `/home/user/samples/` and are skipped otherwise. What those files taught the reader: Publisher 2000 table records (columns, rows, spans, cell text; cell borders and fills are not decoded and become a hairline grid, with a warning); a Publisher 97 record variant without the rotation word; table cell boundaries in the Quill stream as character offsets; WordArt objects as centred text frames in the shape's colour (warp effects are not reproduced); approximate presets for 30 more Office Art shape types, counted in a warning. A second pass compared every file with LibreOffice 24.2, whose Publisher import uses the Document Liberation Project's own reader: only the master pages and the pages listed before the scratch-area boundary become pages (special pages after it had produced phantom pages; page counts now agree with the reference on 18 of 21 Publisher 2002+ files), 1.5 sp line spacing means 1.5 single lines (180% of the font size, which had made text 1.5–2× too loose and overflow its boxes), numbering type 0xFF is "no list", bullet 0xB7 is U+2022, and group children are written in page coordinates. Where the reference is weaker: it has no linked text (each story repeats in every frame of the chain), draws WordArt as black shapes, drops list numbering and adds an empty first page to Publisher 2000 files. Publisher 2000 table cell border styles are decoded (chunk 0x4E: per-cell side records with width and colour): tables without borders print none, and bordered edges are drawn as lines grouped with the table, since the model has only table-wide borders; Publisher 2000 cell fills are not decoded (no sample has one). Known limits: the Publisher 2007 schedules set their table header text in the palette's white over cells whose fill is not stated anywhere in the file (the reference does not show it either), so that text shows white on white; fonts that are not bundled (for example Elephant, Bodoni MT Black, Comic Sans MS) fall back to the closest bundled face, so line breaks can differ from Publisher's.


## QuarkXPress (.qxp, .qxd, .qxt) and XPress Tags (.xtg)

QuarkXPress documents are identified by the `MMXPR` (Mac, big-endian) or `IIXPR` (Windows, little-endian) header at offset 2; Mac files wrapped in MacBinary are unwrapped first. `src/io/qxp/` reads versions **3.1, 3.3 and 4.x** from the public description embodied in the Document Liberation Project's reader (docs/LEGAL.md, *Format references*): the 256-byte block chain and the obfuscation of 3.x and 4.x files; fonts, colors, H&Js, line styles, character and paragraph formats; page settings and spreads (facing pages split by object position); text boxes with columns, gutter, insets and vertical alignment, chained across boxes and pages; text with font, size, bold, italic, underline, strike, caps, superscript, subscript, baseline shift, color and shade; paragraph alignment, indents, space before and after, absolute leading, hyphenation from the H&J, rules and tab stops; box fills (solid, two-stop gradients) and frames (width, color, dash, arrowheads); lines; rectangles, rounded, concave and beveled boxes and ovals as presets; polygon (3.x) and Bézier (4.x) boxes and lines as custom paths; 4.x text paths as text on a path; groups; runaround as square wrap; rotation and flips. Picture boxes use an embedded preview when the file carries one; otherwise the frame is empty and named after the missing picture, because QuarkXPress links pictures rather than embedding them.

Character formats include horizontal scale, manual kerning, tracking, baseline shift (in points: QuarkXPress stores it as a fraction of the type size), outline and shadow type; box skew is read (no corpus file uses it, so its sign is unverified). Master pages with objects are imported as masters but not applied, because QuarkXPress keeps copies of master items on each page (a warning says so); text paths inside a chain take their slice of the story. Not recovered: margin and column guides, style sheet names (formats are applied flat), 4.x color names, text inside polygon or Bézier boxes (the outline is drawn as a shape grouped with the frame; the text is set in the box's rectangle and a placed picture is not clipped to the outline), exact custom dash lengths (the nearest preset is used), rectangular and diamond blends (drawn as radial), per-run languages (Mac files decode as Mac Roman), OLE pictures. QuarkXPress 3.0 and earlier, 5 and later, and book or library files fall back to text and pictures recovered from the bytes, with a warning naming the reason. The reader has been run against the 163-file QuarkXPress seed corpus of the Document Liberation Project (3.1, 3.3 and 4.0 files from Mac and Windows: text boxes, formatting, linked texts, gradients, dashes, arrows, polygons, Bézier boxes and lines, groups, facing pages, masters, tabs, text paths, runaround, pictures): 158 read with their layout; the five that fall back are two libraries, a book, a 3.3 library and a 1 KB QuarkXPress 1 file. What those files taught the reader: the linked-picture file record of 3.3 picture boxes, the 3.1 picture box layout, 4.x line colours from the frame record, keeping the objects read before a damaged one, master counts above 127. A second pass compared every file with LibreOffice 24.2 (libqxp) and fixed: paragraph spacing (the Body style's space after had loosened every text by about 1.5×), blend angles and circular blend colours, arrowhead ends, the direction of 3.x lines rising to the right, polygon and Bézier outlines on text and picture boxes, vertex lists (point counts that are not a multiple of three are straight-edged), frames drawn inside the box with insets grown to match, dashes and stripes in line-width units, hairlines (zero-width lines and text paths, 0.25 pt in their own colour), text-path alignment, and groups straddling the spine. Every page count agrees with LibreOffice where LibreOffice opens the file; it cannot open four documents this reader reads (shapes, shapes-31, shape-31-2, test). Where the reference is weaker: it ignores vertical alignment and runaround, drops vertex-list polygons, and draws every Bézier node after the first as a smooth node (reflecting the previous control point), so corner nodes differ from QuarkXPress; this reader uses the stored control points. Corpus tests run when the files are present under `/home/user/samples/qxp` and are skipped otherwise.

**XPress Tags**, QuarkXPress's documented tagged-text export, is read properly by `src/io/xpressTags.ts`: the version and encoding header, `@name=` style sheet definitions (alignment, indents, leading, space before and after, size, font), `@name:` paragraph styles, and the character tags for bold, italic, underline, strike, caps, small caps, superscript, subscript, size, font, color and tracking, plus new lines, tabs and special characters. Page geometry is not part of the format; the text flows into frames from the first page.


## PageMaker (.pmd, .p65, .pm6, .pmt)

PageMaker 6.5 and 7 save the publication as an OLE2 compound file whose `PageMaker` stream holds the record store; PageMaker 6.0 writes the record store directly (six zero bytes, the byte-order marker at offset 6, the version byte at 0x2a). Both forms are recognised. `src/io/pagemaker/` reads PageMaker **6.0, 6.5 and 7.0** files (Mac and Windows) from the public description embodied in the Document Liberation Project's reader (docs/LEGAL.md, *Format references*): the table of contents of typed records; page size and count; single- or double-sided placement (objects are stored relative to the page center or the spine); fonts and colors (RGB, CMYK and HLS converted); text blocks as text frames (each its own story: PageMaker's threads are not linked yet) with font, size, bold, italic, underline, strike, caps, superscript and subscript with size and position, color with tint, kerning as tracking, paragraph alignment, indents, spacing, hyphenation, keep options and rules; rectangles and ellipses with solid, paper and pattern fills and dashed or dotted strokes; lines from their end points; polygons as custom paths; groups; placed TIFF bitmaps as pictures (through the app's TIFF decoder); rotation from the transform records. Metafiles become empty frames with a warning; skew comes from the transform record (it matches LibreOffice on the skew samples); master pages are records of type 0x2F (two per master, left and right, each naming its shape list) and are imported and applied by side (every master in the corpus is the empty Document Master, so this is verified on a file built in code; the import says so). PageMaker 5 and earlier fall back to text and pictures recovered from the bytes.

The reader has been run against the 27-file PageMaker seed corpus of the Document Liberation Project (6.0, 6.5 and 7 files from Mac and Windows: shapes, strokes, fills, rotation, skew, groups, text in shapes, text formatting, paragraph formats, hyphenation, rules, single- and double-sided multi-page files, a template): all 27 read with their layout. What those files taught the reader: the compound-file wrapper, 16-bit colour and tint fields in the file's byte order, the 24.8 fixed-point stroke width, line end points, the 136-byte shape records of 6.0, group markers, signed paragraph indents, spread placement around the spine, polygon points relative to the box centre. A second pass compared every file with LibreOffice 24.2 (libpagemaker) and fixed: a carriage return at the end of a character run is a line break inside the paragraph (address blocks had run together), paragraph properties are set explicitly so the Body style no longer leaks in, leading is read from the character records (tenths of a point, 0xFFFF = auto) and the auto-leading percentage from the paragraph record, superscript and subscript are scaled once, the paragraph rule width is 24.8 fixed point, and non-printing objects (shape flag 0x0004) go on a visible "Non-printing (PageMaker)" layer, with a warning to hide it before printing. Where the reference is weaker: it reads every line's tint as 0 and so draws no lines, writes each paragraph end as an extra line break, ignores leading, and renders nothing for the Mac `shapes` file. Mac files store the colour model one bit lower than Windows files (every Mac colour had come out black). The 30-byte character record is mapped in full: outline and shadow type, horizontal scale (tenths of a percent), track (approximated per em), no-break spaces, baseline shift (twentieths of a point); reverse type comes out as paper-coloured text. Not reproduced: custom tab stops (no corpus file has one, so their record is unknown; default stops and the hanging-indent stop apply), per-line leading (the model has one value per paragraph; the leading most characters carry is used), the small-caps size. No corpus file holds a placed bitmap, so picture decoding is verified on files built in code only. Corpus tests run when the files are present under `/home/user/samples/pmd` and are skipped otherwise.


## FrameMaker MIF (.mif)

Maker Interchange Format is FrameMaker's documented text format. `src/io/mif.ts` reads the page size, body pages with their text rectangles (frames with columns), the paragraph catalog (alignment, indents, space before and after, leading, font family, size, weight, angle, hyphenation, next tag, bullets) and the text flows: paragraphs with their tags and local formats, inline font changes, tabs, hard returns and special characters, chained through the rectangles they run through. Tables, anchored frames, graphics, variables (kept as `[Name]`) and master pages are not read yet.

## Text and pictures

Place Text File (`insert.textFile`) and the open path share `src/io/textImport.ts`:

- `.txt`: paragraphs on blank lines; single line breaks inside a paragraph are kept as paragraphs (Tools ▸ Clean Up Pasted Text joins them);
- `.md`: `#`…`###` headings become Heading 1–3, `-`/`*`/`1.` lists become Bullet List / Numbered List, `>` becomes Pull Quote, fenced code becomes the Code character style, `**bold**`, `_italic_`, `` `code` `` and links become runs;
- `.rtf`: paragraphs, bold, italic and underline from the control words; fonts and colors are not read;
- `.docx`: paragraphs, heading styles (Heading 1–3 / Title), lists, bold, italic and underline from `word/document.xml`;
- `.html`: headings, paragraphs, lists, blockquotes, bold, italic, links.

Pictures: the type is sniffed from the bytes (`mimeOf`), the pixel size read from the header (`headerSize`) or by decoding; the frame is sized at the picture's resolution (`dpi` from the file when present, otherwise 72 ppi) and fitted inside the margins. TIFF files are converted to BMP in the app (`src/io/tiff.ts`) because browsers do not show TIFF.

## PDF export

`src/export/pdf.ts` is QuillPress's own writer (no PDF library):

- one PDF page per publication page (or per spread), with `/MediaBox` grown by the bleed and `/TrimBox`/`/BleedBox` set, crop marks optional, and `/PageLabels` from the sections;
- text set from the same line layout as the screen (`src/render/text.ts`) in the publication's **own fonts, embedded as subsets**: every bundled family (Tinos, Arimo, Cousine, Carlito, Caladea, Gelasio, EB Garamond, Libre Baskerville, Lato, Merriweather, Open Sans, Courier Prime) and the names they stand in for (Times New Roman, Arial, Courier New, Calibri, Cambria, Georgia, Garamond, Baskerville, Aptos) are converted from WOFF to TrueType (`src/export/fonts/`), subset to the glyphs used and written as CIDFontType2 fonts with Identity-H encoding and a ToUnicode map, so any Unicode character the face has prints and copies out as text; fonts QuillPress does not bundle (Segoe UI, Verdana, Impact…) print in the same bundled fallback face the screen uses (Carlito, Tinos or Cousine), with a warning, so line breaks on paper match the screen; Latin Extended, Cyrillic and Greek come from the bundled faces' subsets, and characters no face has are counted in a warning; runs of one style are written as one `TJ` array with exact word adjustments so text extraction keeps the words apart;
- footnotes and their separator rules, anchored objects where the text put them, and text on a path glyph by glyph;
- shapes and lines as paths (the preset geometry's SVG path is translated to PDF operators), fills (solid, axial and radial gradient shadings, hatch patterns as tiling patterns, picture fills), strokes, dashes, arrowheads, paragraph rules, hard-edged drop shadows (no blur; glow and soft edges are not exported), run highlights, opacity (`ExtGState`) and link annotations;
- pictures: JPEG embedded as is (`DCTDecode`, gray/RGB/CMYK), other formats decoded to RGB and compressed (`FlateDecode`) with an `SMask` for transparency; without a canvas (tests, Node) PNG is decoded by `src/io/png.ts`;
- document information from File ▸ Properties (strings in UTF-16 where they need it; content streams are Latin-1 bytes).

The writer is checked on exports of corpus files and templates with poppler (`pdfinfo`, `pdffonts`, `pdftotext`, `pdftoppm` compared with the on-screen render) and pypdf's strict reader (`tests/unit/pdfExportCheck.test.ts` covers the structural parts).

Printing to PDF from the system dialog (File ▸ Print) goes through the SVG renderer instead and gives the same fonts; the export is the smaller, vector file for the printer.

## Other exports

- **SVG and pictures:** the page renderer's SVG with `@font-face` rules for the bundled fonts inlined, so it looks the same anywhere; PNG and JPEG are rasterized from it at a chosen width.
- **Web page:** every page as inline SVG (text stays selectable and searchable), a page navigation, and the stories as flowing text for phones and screen readers.
- **Text and Markdown:** all stories in order; Markdown maps heading, list and quote styles back to syntax.
- **Package:** `.qpp`, `.sla`, PDF, web page, a `Links/` folder with every picture, and `Package report.txt` (pages, fonts, pictures).

## Encryption

`.qppe` files are encrypted with AES-256-GCM using a key derived from the password with PBKDF2-SHA-256 (`src/util/crypto.ts`, shared with the suite). A wrong password is reported as such; the recovery engine cannot repair encrypted files without the password.
